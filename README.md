# quick ARC cache introduction:
An Adaptive Replacement Cache (ARC) is a self-tuning, high-performance page replacement algorithm developed at IBM Almaden Research Center. It improves upon traditional caching policies like Least Recently Used (LRU) by dynamically balancing between recency (how recently a page was accessed) and frequency (how often it is accessed) without requiring manual tuning or a priori knowledge of the workload.

It consists of 4 LRU's, 2 of them serving the purpose as the main components of the caching algorithm itself, and the other 2 being *ghost* LRU's, an ARC also consist of an paramater (lets call it *p*) to which influences the decision to which of the 2 primary LRU's should it evict from, lets consider the *ghost* LRU's *B1* and *B2* for this explanation, and *T1* and *T2* for the 2 primary LRU's.

Lets say you have an ARC cache in your backend, and it experiences an *cache miss*, in which case the cache data would be fetched and placed into *T1* initially, and if it is accessed once more, then it is promoted to *T2* with the frequency of the number of times it is retrieved being preserved, to which eventually if requests are no longer accessing that cache data then it will be demoted down to *T2's* ghost layer (such being *B2*) ONLY if it were evicted, if the cache data is suddenly requested for whilst at *B2* then it is promoted back to *T2*, and the same relationship goes for *B1* aswell as *T2*.

And such, when an cache data is promoted from *B2/B1* to *T2/T1* then it also influences *p's* decrease/increase, eg. if an element is promoted from *B2* to *T2*, then *p* is decreased inorder to allocate more space for *T2*, this is because *T1* and *T2* both have target allocations, lets say *T1's* target allocation is 70 and *T2's* is 30, if *p* is increased then it would allocate more space to *T1*, and if *p* were to decrease, then it would allocate more to *T2* . However, eviction is also influenced from either LRU's *ghost* LRU hit, ie. if *B1* were to experience an *ghost* hit then the ARC cache would increase *p* to favor *T1* more in allocation size, and evict from *T2* instead, this is due to if *B1* were to experience a *ghost* hit then it is most likely that *T1* may include cache data that may be fetched more so than *T2*.
